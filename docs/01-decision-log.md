# 01. 결정 기록 (Decision Log)

> **결정의 역사와 미결 사항**의 단일 출처다. 역사 기록이므로 현재 상태의 출처는 아니다.
> 현재 상태는 각 단일 출처 문서를 본다 ([환경 규칙 ENV-3](../.claude/environment/Environment-Setting-Rules.md#env-3-문서-체계와-진실-단일성)).

## 미결 사항
- S-CURT 프로그램 확인: 공개 자료에서 찾은 것은 **고려대 세종캠퍼스** KUS 대학혁신사업단의 **Short-term CURT**(단기형)였다. 이 연구가 같은 프로그램인지 연구자 확인 필요.
- `docs/03-rules.md`의 **(제안)** 항목 확정.
- 헤드리스 첫 임포트 때 URP 머티리얼 업그레이드 대화상자가 batch 모드라 뜨지 못했다. 분홍색 머티리얼이 보이면 따로 확인.
- GitHub push: Claude의 push는 권한 설정에 막혀 있다. 연구자가 직접 push하거나, Claude에게 push 권한을 허용해야 한다.

## 2026-09-29

### 시작 요청
- Infinity Map을 가진 2D 탑뷰 게임 초안. Unity CLI 및 플러그인 사용. 먼저 프로젝트를 생성하고 헤드리스로 실행.

### 결정
1. **범위:** 플레이어는 WASD 이동만.
2. **성격:** 게임을 주제로 한 연구, 고려대학교 S-CURT 연구.
3. **1단계 목표:** 무한 맵 생성 자체에 도전.
4. **코드 원칙:** 최대한 단순하게, 연구자가 이해할 수 있는 범위 안에서.
5. **역할 분담:** 메인 에이전트는 대화와 문서 저장, 생성과 검색/문서화는 서브에이전트(검색 10분 제한).
6. **에디터:** 이미 설치된 6000.3.21f1(Unity 6.3 LTS) 사용, 추가 설치 없음.
7. **템플릿:** Universal 2D(URP 2D). Tilemap 등 2D 패키지가 기본 포함되어 있어 선택.
8. **프로젝트 위치:** 저장소 루트 = Unity 프로젝트 루트. 작업 폴더가 이미 있어 CLI가 바로 생성하지 못해, 임시 폴더에 만든 뒤 옮김.
9. **플랫폼, 수익화:** 연구 프로젝트이므로 해당 없음.
10. **플레이어 디자인:** Figma(홈 > 새 캔버스) 제안이 있었으나 더 편리한 **SVG로 결정** (근거: [02-player-design.md](02-player-design.md)). 흰색 네모에 캐릭터성, 상하좌우 방향이 보이게.
11. **소스 관리:** GitHub private 저장소 (주소는 환경 규칙 ENV-8).
12. **문서 체계:** 아키텍처 문서, Claude 문서, docs 공간을 둔다. 규칙 문서를 추가하고 CLAUDE.md에 규칙과 아키텍처를 링크(`@경로`로 자동 읽기). `Docs/`는 `docs/`로 변경.
13. **색인:** 모든 폴더에 `..INFO.md`(1줄 설명, 2줄 빈 줄, 3줄부터 자유), 이를 모아 `INDEX.md`를 자동 재구성하는 도구를 두고 매 작업 후 실행. 모든 것은 상대 경로로 파악.
14. **환경 규칙 분리:** 환경 구성 지시문은 "Environment Setting Rules" 한 파일에 모으고, 추후 스킬로 뺄 수 있게 프로젝트와 구분되는 공간(`.claude/environment/`)에 둔다. (파일 이름은 링크가 깨지지 않도록 공백 대신 `-` 사용)
15. **자동화 도구:** 모두 `sub-tools/`에 모은다. 이에 따라 `Art/svg2png.py`도 `sub-tools/`로 이동.
16. **특수기호:** 가운뎃점(U+00B7)과 엠 대시(U+2014)는 쓰지 않는다.
17. **코드 원칙 추가:** SOLID 원칙과 디자인 패턴을 쓴다. **진실 단일성을 가장 주의**한다. 이에 따라 문서도 사실마다 단일 출처를 정하고 나머지는 링크로 바꿈. 플레이어 코드는 SOLID로 리팩터링(입력 Strategy, 방향 변경 Observer).
18. **백그라운드 실행:** 시간이 걸리는 명령은 백그라운드로 돌리고, 그동안 결과에 의존하지 않는 작업을 먼저 한다 (환경 규칙 ENV-9).
19. **캡처:** 캡처 디렉터리(`captures/`)를 두고, 이후 모든 작업 보고는 캡처를 포함한다. 용어는 "스크린샷" 대신 "캡처". 촬영은 `sub-tools/capture.py`로 자동화 (환경 규칙 ENV-10). 기존 씬 캡처(`Art/Player/scene-preview.png`)는 아트가 아니므로 `captures/`로 옮김.
20. **무한 맵 구현 시작:** 코드와 디자인(타일 아트)을 여러 서브에이전트로 병렬 생성. 두 쪽이 서로 기다리지 않도록 계약(TileType 순서, Tile 에셋 경로)을 먼저 정하고, 끝나면 통합 에이전트가 씬에 연결, 검증, 캡처.
