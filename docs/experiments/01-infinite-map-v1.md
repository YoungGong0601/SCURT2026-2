# 실험 01. 무한 맵 1차 구현 검증

> 2026-09-29, 상태: 1차 완료
> 무한 맵 1차 구현의 **측정 결과**의 단일 출처다. 구조는 [ARCHITECTURE.md](../../ARCHITECTURE.md), 설정값은 `Assets/Data/MapSettings.asset`.

## 조건
- 생성기: `PerlinTileGenerator` (시드 오프셋 + Perlin 노이즈 1옥타브 + 임계값)
- 설정: `MapSettings` 기본값 (seed 12345, 청크 16×16, 로드 반경 2, 프레임당 1청크, 노이즈 배율 0.05, 임계값 0.35 / 0.45 / 0.7)
- 환경: 헤드리스 Unity 에디터 (batchmode). 시간 측정값은 에디터 모드 참고값이며 빌드 성능과 다를 수 있다.

## A. 단위 검증 (코드 에이전트, 씬 없이)

### 결정론
| 검사 | 결과 |

| 같은 생성기를 역순으로 다시 호출 | 4096/4096 일치 |

| 청크 (0,0)을 지웠다 다시 만든 뒤 해시 | 같음 (-683510633) |

### 스트리밍 (프리뷰 씬에서 Update 직접 호출)
- 원점에서 Update 1회 후 활성 1청크 (프레임당 1개), 41회 후 활성 25청크.
- 6400칸 모두 생성기 결과와 일치 (`SetTilesBlock` 배열 순서 확인).
- 청크 (5,0)으로 이동: 활성 30청크, 누적 생성 50. 거리 3인 청크는 남고(언로드 반경 r+1), 더 먼 청크는 지워짐.
- 음수 영역 (-20.5, -0.5)로 이동: 중심 청크 (-2,-1), 활성 25청크, 불일치 0.

### 생성 시간 (에디터 모드 참고값)
- 청크당 평균 0.193 ms, 최대 4.391 ms (최대값은 첫 호출 JIT 영향으로 추정, **미확인**).
- `GetTile` 65,536회 약 2.36 ms.

### 타일 분포 (256×256, 좌표 -128~127)
| seed | 물 | 모래 | 풀 | 숲 |

| 12345 | 26.3% | 20.7% | 43.4% | 9.5% |

## B. 통합 검증 (씬, Play 모드, 자동 입력)

### 방법
- Play 중 `AutoMoveInput`을 붙이고 `PlayerMovement.SetInput`으로 교체 (키보드 없이 걷기). 속도 5.
- 경로: 직선 0 → +100 → -100 → 0, 대각선 0 → (+64,+64) → (-64,-64) → 0.
- PlayerLoop의 PostLateUpdate에서 **매 프레임** 표본 (약 275만 프레임, 헤드리스 약 16,000 fps).

### 활성 청크 수
| 구간 | 최소 | 최대 | 머무는 값 |
|---|---|---|---|
| 시작 (움직이기 전) | 25 | 25 | 25 |
| 직선 이동 | 25 (첫 구간만), 이후 26 | 30 | 30 |
| 대각선 이동 | 26 | 34 | 34 |
| 끝 (원점에 멈춤) | 34 | 34 | 34 |

- 이론상 최대 7×7 = 49, 실측 최대 34. **개수는 늘 제한 안에 있었다.**
- 움직인 뒤에는 25로 돌아가지 않는다. 언로드 반경이 r+1 = 3이라 지나온 쪽의 거리 3 줄이 남기 때문 (직선 뒤 6×5 = 30, 대각선 뒤 34).
- 되돌아설 때 새로 만든 청크는 0개. 언로드 반경을 로드 반경보다 크게 둔 효과(이력 유지, hysteresis)가 확인됨.

### 청크 생성 시간
- 걷는 동안 만든 246청크: 중앙값 0.178 ms, p95 0.240 ms, 최대 0.422 ms.
- 누적 (시작 포함 271청크): 평균 0.209 ms, 최대 5.578 ms. 최대값은 **맨 첫 청크 한 번뿐** (새로 Play해도 첫 청크 4.401 ms). 첫 호출 준비 비용으로 보임.
- 헤드리스에서는 fps가 매우 높아 프레임 시간은 연구 데이터로 쓸 수 없다. 청크 ms만 유효.

### 결정론
- 청크 8개(음수 포함)의 `ChunkHash`: 시작, 직선 복귀 후, 대각선 복귀 후 세 시점 모두 같음.
  (0,0) = -683510633, (-1,-1) = -334620106, (-2,1) = 167205046, (2,-2) = -58558013, (-7,0) = -1710443433, (6,0) = -1723294155, (-4,-4) = -277244320, (4,4) = -2137690466
- Tilemap에 실제로 들어 있는 청크 (0,0) 내용도 세 시점 모두 같음. 이 청크는 x = 100까지 가는 동안 지워졌다가 다시 만들어진 것.
- 원점 주변 25청크 모두 "Tilemap 내용 = 생성기 결과" (불일치 0).

## 관찰과 다음 질문
- **로드 영역이 플레이어 중심이 아니다.** 원점의 플레이어는 청크 (0,0)(타일 0~15)의 모서리에 서 있어서, 로드 영역(타일 -32~47)이 한쪽으로 치우친다. 청크 안 위치에 따라 앞쪽 여유가 32~47타일로 달라진다.
- 언로드는 중심 청크가 바뀌는 프레임에 5~9청크를 한꺼번에 지운다. 이것이 끊김을 만드는지 측정 필요.
- 첫 청크 4~5 ms의 원인(JIT 등) 확인 필요 (**미확인**).
